# Job queue Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Turn the studio's fire-and-forget background jobs into a managed queue — bounded concurrency by resource class, a plan that survives a restart, cooperative stopping, and a Jobs screen.

**Architecture:** A pure `job_queue.py` holds the queue, the two pools, the state file and the transitions, and spawns no threads. A `studio/worker.py` thread drives it, calling the existing `start_*_job` functions unchanged. A `CancelToken` is threaded into the long-running work as a parameter, checked at each kind's own safe point. Stream transcription becomes a job kind of its own.

**Tech Stack:** Python 3 (stdlib), FastAPI (routes only), React 19 + Mantine + TypeScript, pytest, Vitest, Playwright-inside-pytest.

## Global Constraints

From the spec and CLAUDE.md. Every task's requirements include these.

- **`job_queue.py` is pure**: no FastAPI, no threads, no `studio` import. It must be importable in a venv that never installed FastAPI, the rule `subtitle_pipeline.py` and `upload_policy.py` follow.
- **No test may reach the network, transcribe, render, upload, read a real API key, import a vendor SDK at module scope, or spend money.** A test that would spend money is a defect.
- **`<workspace>/jobs.json` never holds an API key.** A detect entry stores channel, event and video id; the key is read from `auth/` when the job starts.
- **A hard stop kills only the subprocess a thread waits on, never the thread.** The thread's own `finally` blocks must still run.
- **`upload` has no stop at any level.**
- **`connect` is never queued** — it opens a browser and waits for a person.
- **`EventLock` stays and is not replaced.** The pools bound load; the lock stops two runs from tearing up one event.
- **`moment_scan.py` may gain the two additive parameters the spec names
  (`should_stop`, `window_cache`) and nothing else.** Its scoring, validation,
  merging, the line-number protocol and `MAX_PER_WINDOW` are untouched, and it
  stays filesystem-free — the disk-backed cache is supplied by `detect.py`.
  Both parameters default to `None`, so every existing caller and all 43 tests
  in `tests/test_moment_scan.py` exercise the unchanged path.
- The six SHA-256 overlay hashes in `tests/test_event_layer_no_regression.py` must never be re-pinned.
- `python3 tools/lint.py` exits 0. Treat a lint failure as blocking: a duplicate test-class name makes pytest silently drop the shadowed class (measured: collection fell 218→216 and still reported "216 passed") and only ruff's F811 catches it.
- Frontend: `npm test` and `npm run build` before committing; **bare `npx tsc --noEmit` is INERT here and proves nothing**. The built bundle at `src/yt_shorts/studio/static/` is committed and must be rebuilt with the sources.

- [ ] **Step 3: Write `cancel.py`**

```python
"""A two-level cancellation request, passed into long-running work.

Python threads are not killable, so stopping is COOPERATIVE: the work
checks this token at points it chooses, where stopping is safe. The two
levels differ only in what happens to a subprocess the work is waiting on -
`kill` additionally terminates it. Neither ever touches the thread.

Injected as a parameter, like `runner`, `logger`, `on_note` and `caller`
elsewhere in this project - never global state, so a test can drive it
directly and count the checkpoints it reaches.
"""

from __future__ import annotations

import threading


class Stopped(RuntimeError):
    """The work was asked to stop and reached a safe point. Not a failure:
    a job that ends this way is `stopped`, not `failed`."""


class CancelToken:
    def __init__(self) -> None:
        self._stop = threading.Event()
        self._kill = threading.Event()

    def request_stop(self) -> None:
        self._stop.set()

    def request_kill(self) -> None:
        # A hard stop is a stop that ALSO kills the subprocess - never a
        # separate mode in which the work would carry on.
        self._stop.set()
        self._kill.set()

    @property
    def stop_requested(self) -> bool:
        return self._stop.is_set()

    @property
    def kill_requested(self) -> bool:
        return self._kill.is_set()

    def raise_if_stopped(self) -> None:
        if self._stop.is_set():
            raise Stopped("stop requested")
```

- [ ] **Step 3: Write the module**

Follow the spec's state list exactly: `queued`, `running`, `done`, `failed`, `stopped`, `paused`, `stopping`, `interrupted`. Two rules that are easy to get wrong and are pinned above:

- `claim_next` **skips** an entry it cannot start and considers the next one. A full cpu pool must not stop a net entry behind it from running.
- A `stopping` entry **keeps holding its pool slot**. It is not finished, and the thread is still using the resource — handing the slot on would oversubscribe silently.

Persist with write-aside-then-`os.replace`, the mechanic `providers.save_api_key` and `render.compose` use.

### Task 10: A producer for `Entry.progress`

**Added 2026-08-01, by the operator's decision, after the final review.** The
Jobs screen shows no progress because nothing writes `Entry.progress`. That was

  transcription that is fine; anything finer needs `logsetup.LineThrottle`,
